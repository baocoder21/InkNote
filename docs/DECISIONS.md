# DECISIONS

- **Modular monolith, plain PostgreSQL** – simple; no Supabase to avoid overlapping with the .NET backend.
- **.NET 9** – the version in use; upgrade to .NET 10 LTS is on the roadmap.
- **IMemoryCache first, Redis later** – add Redis only when running multiple instances.
- **PWA for desktop** – Tauri/Electron only if deep OS integration is needed.
- **ng-zorro-antd 22 (MIT), NOT PrimeNG** – PrimeNG was tried first in Phase 2 (user's choice) and dropped: PrimeNG 22 requires a PrimeUI license key (free Community tier, but needs registration; without a key it shows a red "Invalid PrimeUI License" badge, and its license forbids removing that mechanism). ng-zorro 22.2 is MIT, has no license check, and declares Angular `^22.0.0` peers. Always read the license terms of a UI library, not only its peer dependencies.
- **ng-zorro setup choices** – its stylesheets are NOT in the `styles` list of `angular.json` any more: the dark build and the light ("variable") build are copied as assets to `/themes/` and one of them is loaded at run time (see the themes decision below); static icon registration (`provideNzIcons`) in `core/ui.providers.ts`; `provideNzNoAnimation()` because `@angular/animations` is not installed; `NzModalService` and `NzContextMenuService` are not root-provided and are provided in `notes.routes.ts` (`NzMessageService` is root-provided). **`ng serve` does not reload `angular.json`: restart it after changing it** (it hid the KaTeX CSS from the user's dev server and from mine).
- **Own design tokens `--ink-*` in `src/styles/_tokens.scss`** – ng-zorro 22 exposes CSS variables only for primary/success/warning/error colors, not neutral ones.
- **Three themes: Light, Dark, Warm (chosen by the user), switched from a button in the sidebar** – `<html data-theme="light|dark|warm">` + design tokens defined per theme in `styles/_tokens.scss` (a new token must be defined in all three). The user fixed background and text colors: **Dark = Nord** (#2e3440 / #d8dee9), **Warm = Kanagawa Lotus** (#f1e9d2 / #4d699b), **Light** (#edeeec / #dc347f); every other color (surfaces, lines, accent, Markdown "special characters", code colors) was chosen and checked for contrast. Default Dark; the choice is saved in `localStorage` (`inknote.theme`). `core/theme.service.ts` applies it; a small script in `index.html` applies it BEFORE Angular starts (no wrong-color flash), so the two must be kept in sync.
- **Known contrast limit of the Light theme (user's choice)**: note text #dc347f on #edeeec is 3.73:1, below WCAG AA (4.5:1) for body text. Headings, links, code and the interface use darker variants (all >= 4.3:1). Comments in code are deliberately dimmer (~4:1) in all themes. Warm's text #4d699b on #f1e9d2 is 4.55:1; Dark's is 9.25:1.
- **ng-zorro cannot show two themes at once**: it ships a dark build and a light build (same selectors) and they cannot be loaded together. They are copied as assets (`/themes/ng-zorro-antd.{dark,variable}.min.css`), `ThemeService` swaps the `<link data-zorro>` (the new one is inserted right after the old one, i.e. BEFORE our own stylesheet, and the old one removed only when the new one has loaded). Light and Warm share the light build; only our tokens differ. Our `styles/_zorro-overrides.scss` restyles buttons, dialogs, menus, inputs, selects, toasts and the view switch with the tokens, in all themes.
- **Editor, code and diagrams follow the theme through CSS variables, no rebuild**: CodeMirror uses our own theme + `HighlightStyle` made of `var(--ink-syn-*)` (`markdown-editor/ink-editor-theme.ts`; `@codemirror/theme-one-dark` was removed, `@lezer/highlight` and `@codemirror/language` are direct dependencies); Shiki uses a "CSS variables" theme (`createCssVariablesTheme`, prefix `--ink-code-`) so code blocks recolor instantly; Mermaid has colors baked into its SVG, so it is re-initialized with its `base` theme fed by the computed CSS colors and the drawn-diagram cache is emptied when the theme changes. In Markdown the special characters (`#`, `*`, backticks, `>`, `-`, link brackets) have their own color (`--ink-syn-mark`).
- **Production build: `inlineCritical: false`** – Angular would inline only the default theme's tokens in `index.html`, so a user who chose Warm or Light would see a flash of dark colors on every load.
- **One sidebar, explorer style (chosen by the user)** – folders (notebooks) contain their notes; loose notes at the top level; tags below. Replaces the earlier navigation column + notes list. Needs ALL notes, so the sidebar loads the full list (summaries only) and groups/sorts/filters it on the client (`explorer-rows.ts`); the API's `?notebookId=` / `?tagId=` filters stay available but the UI does not use them. Inside a folder notes are sorted pinned first, then by TITLE (not by last edit: autosave would make the note under your cursor jump).
- **Actions in right-click menus plus a hover "..." button; no Save button, no trash icon in the editor (user's request)** – notes save by autosave and Ctrl+S (status in the footer). Deleting a note is in the note's menu in the sidebar, with a confirmation. The toolbar has two icons only: new note, new folder; tags are created from a "New tag…" row.
- **"Current folder"** = the last folder clicked, or the folder of the open note; "new note" and "new folder" use it. Open folders are remembered in `localStorage` (guarded with try/catch).
- **Name dialog takes the focus after one tick** – the modal moves focus to its own frame after opening; without the wait the input was never focused (found with a real browser, jsdom cannot show it).
- **Initial bundle budget: warning 1.2 MB, error 1.5 MB (raw)** – ng-zorro ships one 571 kB CSS file (~52 kB gzip); total transferred is ~186 kB.
- **Markdown pipeline: unified (remark/rehype) + KaTeX + Shiki + Mermaid, sanitized by DOMPurify** (Phase 3). All MIT (DOMPurify: MPL-2.0 OR Apache-2.0). Two XSS layers: remark drops raw HTML; DOMPurify cleans the final HTML (SVG/MathML allowed for KaTeX, `<annotation>` allowed, forms/style/button forbidden, links forced to `target=_blank rel="noopener noreferrer"`). `MarkdownPreviewComponent` sets `innerHTML` itself because Angular's sanitizer would strip the inline styles KaTeX/Shiki need; this is the only allowed place.
- **Shiki with explicit languages + JS regex engine** – 11 languages bundled and lazy-loaded; unknown fences fall back to plain text; no WASM. Add a language in `highlighter.ts`.
- **Mermaid loaded only when a note has a diagram** (dynamic import), `securityLevel: 'strict'`. Drawn diagrams are cached by source text (max 50, cloned DOM nodes, errors not cached) so unchanged diagrams are not redrawn after every keystroke pause.
- **Preview delay 50 ms via `PREVIEW_DELAY_MS` token** (was 150 ms): measured render takes 10-120 ms, so the wait dominated the perceived lag.
- **CodeMirror 6 wrapped by hand** (not a third-party Angular wrapper) – fewer dependencies, and the sync with the `value` model signal is ~10 lines.
- **Autosave: debounce 1.5 s via RxJS, delay injectable (`AUTOSAVE_DELAY_MS`)** – `exhaustMap` avoids overlapping saves; no autosave during a 409 conflict; the draft is also saved when switching notes or leaving the page; `beforeunload` warns when dirty. Limitation until Phase 7 (local-first): closing the browser inside the delay window can still lose a few seconds of typing.
- **`NotesStore.createNote` does not select the new note** – the editor still holds the previous note's draft and saves it before loading the new one.
- **npm `overrides` pins `katex` to the patched 0.19.1** – `rehype-katex`/`remark-math` depended on an older nested copy with a (low) advisory; `npm audit` is clean.
- **Store methods are `async` + `firstValueFrom`** – easier to read and test than `rxMethod` while learning; `rxMethod` can be adopted later for streams (e.g. search-as-you-type).
- **Container vs presentational components** – `NotesPageComponent` talks to the store; `NotesListComponent` only receives inputs.
- **State: Signals + SignalStore, RxJS for HTTP/streams** – RxJS is not used as a store.
- **EF Core 9.x (not 10)** – EF Core 10 requires .NET 10. Versions are pinned exactly in the csproj; `Microsoft.EntityFrameworkCore.Relational` is referenced directly so the test project resolves the same EF version as the API.
- **Guid v7 ids generated by the application** – lets offline clients create notes without ID clashes (Phase 7) and keeps index inserts ordered.
- **One shared `AppDbContext`, module folders inside one project** – simplest while learning; split into projects/DbContexts later only if needed.
- **Optimistic concurrency with `Version`** – update requests carry the last seen version; mismatch returns 409. Reused by sync in Phase 7.
- **Soft delete through an EF query filter** – rows stay (needed for sync); queries hide them automatically.
- **Dev DB on host port 5433** – a local Windows PostgreSQL service already uses 5432. Connection string lives in user-secrets.
- **Swagger UI (not Scalar) for API docs** – more familiar to the user. OpenAPI JSON is generated by .NET 9's built-in `AddOpenApi`; only the UI package `Swashbuckle.AspNetCore.SwaggerUI` is added.
- **Tests use real PostgreSQL via Testcontainers** – no mocked DbContext; real migrations are applied.
- **Phase 4: three modules (Notes, Notebooks, Tags) linked by Id + small contracts** – Note stores `NotebookId` and `NoteTag(NoteId, TagId)` rows (the join table belongs to Notes: a note's tags are part of its data). Modules talk only through `Contracts/` interfaces (`INotebookLookup`, `ITagLookup`, `INotebookUsage`); there are no cross-module navigation properties or queries. The one exception is the EF configuration, which names the other module's type to create the foreign key. The contracts point both ways (Notes -> Notebooks/Tags and Notebooks -> Notes) but never form a runtime cycle; if this grows, replace with domain events.
- **Notebook tree = flat table with `ParentId`; the API returns a flat list** – the client builds the tree. Moving a notebook rejects itself/descendants as the new parent (cycle check walks up the parents).
- **Deleting a notebook is refused (409) unless it has no sub-notebooks and no live notes** – no silent data loss. Notebook and Tag use hard delete for now (note: sync in Phase 7 may need tombstones). FK `notes.notebook_id` is `ON DELETE SET NULL` so soft-deleted notes never block it; `note_tags` rows cascade with their tag.
- **Organization (notebook, pin, tags) has its own endpoint `PUT /api/notes/{id}/organization`** – so editor autosave never overwrites it. It bumps `Version` (conflict detection) but not `UpdatedAt` ("updated" = content edited), so pinning does not reorder by date. Tag names are unique ignoring case via a `NormalizedName` unique index.
- **List order: pinned first, then `UpdatedAt` desc; filters `?notebookId=` and `?tagId=`** – a notebook filter matches exactly that notebook (not its sub-notebooks).
- **Phase 4 frontend: the tag filter lives in the URL** (`/notes?tag=<id>`) – survives reload, shareable, Back button works. Angular binds query params to the page's `tag` input (`withComponentInputBinding`) and passes it to the sidebar. Links that open/leave a note use `queryParamsHandling: 'preserve'`; creating a note drops it (the new note has no tags and would be hidden).
- **`OrganizationStore` (notebooks, tags) separate from `NotesStore`** – changes rarely, read by sidebar and editor. The notes page loads it; the editor only reads it.
- **Organization changes merge only version/notebook/pin/tags into `selected`** and the editor resets its text only when the SAVED text changes (`updatedAt` is part of the key). Otherwise the server's reply (last saved text) would overwrite an unsaved draft. While an organization request runs, `saving` is true so autosave and the pickers cannot race on the same version.
- **Notebook tree is built on the client** (`buildNotebookTree`, pure function) from the flat API list; drawn by a self-including `ng-template` (no recursive component).
- **Known limits (on purpose)**: moving a folder (change parent) has API support but no UI (no drag and drop either); tags are created in the sidebar only (not from the editor's picker); if an organization request fails, a picker may keep showing the value the user chose until the next reload; the sidebar is a fixed 18 rem (no resizing, no small-screen layout).
- **The first page load got lighter**: moving `NzModalService`/`NzContextMenuService` from the app-wide providers to the lazy notes route took the initial bundle from 1.18 MB (budget warning at 1.2 MB) to 1.00 MB raw. Lazy loading applies to providers too, not only to components. With the themes, ng-zorro's 590 kB stylesheet left the bundle (it is an asset loaded at run time), so the initial total is now ~444 kB raw / ~117 kB transferred.
- **Backend commands while the API runs locally** – a running API locks `bin/Debug`. Use `--configuration Release` for `dotnet test` and `dotnet dotnet-ef ...` (output goes to `bin/Release`) instead of stopping the API.
- **Note status** (`None | Active | OnHold | Completed | Dropped`, same set as Inkdrop) lives on the Note and is changed through the organization endpoint with the notebook, pin and tags (one request, one `Version` bump). The enum travels as its NAME in JSON (`[JsonConverter(JsonStringEnumConverter<NoteStatus>)]`) and is stored as text (`HasConversion<string>`, default `"None"`), so clients and database rows never depend on the enum's numbers. `IsInEnum()` rejects numbers outside the set. `status` is a required field of the organization request (not optional): a client that forgets it would otherwise silently reset every note to None.
- **Unreadable request bodies answer 400, not 500** – `BadRequestExceptionHandler` (an `IExceptionHandler`) maps `BadHttpRequestException` (malformed JSON, unknown enum name...) to a ProblemDetails 400 without echoing the exception message. Before, `UseExceptionHandler()` turned every such client mistake into a 500.
- **The editor looks like the preview while you type** – a CodeMirror ViewPlugin (`markdown-live-style.ts`) adds a CSS class to whole LINES from the Markdown syntax tree (headings h1-h6, quote, fenced/indented code, table, rule) and `HighlightStyle` styles the inline pieces (bold, italic, ~~strike~~, `code`, links). The Markdown marks (`#`, `*`) stay visible, in their own color: what you see is still exactly what is in the file (hiding marks off the active line, Obsidian-style, was left out on purpose: more code and cursor edge cases). Prose uses the same sans-serif font and line height as the preview; code and tables stay monospace so `|` columns line up.
- **The editor uses the GFM dialect** (`markdown({ base: markdownLanguage })`). The default of `@codemirror/lang-markdown` is plain CommonMark: tables and `~~strikethrough~~` were not even recognized in the editor before. It is also what the preview supports (remark-gfm).
- **No status line under the editor** ("All changes saved · Updated ... · Version n" removed at the user's request). Autosave failures still show a toast and the 409 banner; the one state that would otherwise be invisible, "too long to save", has its own error alert above the panes.
- **Edit/Split/Preview switch sits in the middle of the toolbar row** (grid `1fr auto 1fr`: the two outer columns are equal, so it is the true center), next to the notebook, status and tag pickers. The notebook picker has a search box (`nzShowSearch`, matches the full "Parent / Child" path); the tag picker (multiple mode) always has one. The tag picker is small and shows one chip plus "+N" so the row never grows taller.
