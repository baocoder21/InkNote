# DECISIONS

- **Modular monolith, plain PostgreSQL** – simple; no Supabase to avoid overlapping with the .NET backend.
- **.NET 9** – the version in use; upgrade to .NET 10 LTS is on the roadmap.
- **IMemoryCache first, Redis later** – add Redis only when running multiple instances.
- **PWA for desktop** – Tauri/Electron only if deep OS integration is needed.
- **ng-zorro-antd 22 (MIT), NOT PrimeNG** – PrimeNG was tried first in Phase 2 (user's choice) and dropped: PrimeNG 22 requires a PrimeUI license key (free Community tier, but needs registration; without a key it shows a red "Invalid PrimeUI License" badge, and its license forbids removing that mechanism). ng-zorro 22.2 is MIT, has no license check, and declares Angular `^22.0.0` peers. Always read the license terms of a UI library, not only its peer dependencies.
- **ng-zorro setup choices** – `ng-zorro-antd.variable.min.css` in `angular.json`; static icon registration (`provideNzIcons`) in `core/ui.providers.ts`; `provideNzNoAnimation()` because `@angular/animations` is not installed; `NzModalService` must be provided explicitly (`NzMessageService` is root-provided).
- **Own design tokens `--ink-*` in `src/styles/_tokens.scss`** – ng-zorro 22 exposes CSS variables only for primary/success/warning/error colors, not neutral ones. Light theme only; dark mode (ng-zorro dark stylesheet + theme switch) is a later, optional task.
- **Initial bundle budget: warning 1.2 MB, error 1.5 MB (raw)** – ng-zorro ships one 571 kB CSS file (~52 kB gzip); total transferred is ~186 kB.
- **Markdown pipeline: unified (remark/rehype) + KaTeX + Shiki + Mermaid, sanitized by DOMPurify** (Phase 3). All MIT (DOMPurify: MPL-2.0 OR Apache-2.0). Two XSS layers: remark drops raw HTML; DOMPurify cleans the final HTML (SVG/MathML allowed for KaTeX, `<annotation>` allowed, forms/style/button forbidden, links forced to `target=_blank rel="noopener noreferrer"`). `MarkdownPreviewComponent` sets `innerHTML` itself because Angular's sanitizer would strip the inline styles KaTeX/Shiki need; this is the only allowed place.
- **Shiki with explicit languages + JS regex engine** – 11 languages bundled and lazy-loaded; unknown fences fall back to plain text; no WASM. Add a language in `highlighter.ts`.
- **Mermaid loaded only when a note has a diagram** (dynamic import), `securityLevel: 'strict'`.
- **CodeMirror 6 wrapped by hand** (not a third-party Angular wrapper) – fewer dependencies, and the sync with the `value` model signal is ~10 lines.
- **Autosave: debounce 1.5 s via RxJS, delay injectable (`AUTOSAVE_DELAY_MS`)** – `exhaustMap` avoids overlapping saves; no autosave during a 409 conflict; the draft is also saved when switching notes or leaving the page; `beforeunload` warns when dirty. Limitation until Phase 7 (local-first): closing the browser inside the delay window can still lose a few seconds of typing.
- **`NotesStore.createNote` does not select the new note** – the editor still holds the previous note's draft and saves it before loading the new one.
- **npm `overrides` pins `katex` to the patched 0.19.1** – `rehype-katex`/`remark-math` depended on an older nested copy with a (low) advisory; `npm audit` is clean.
- **Store methods are `async` + `firstValueFrom`** – easier to read and test than `rxMethod` while learning; `rxMethod` can be adopted later for streams (e.g. search-as-you-type).
- **Container vs presentational components** – `NotesPageComponent` talks to the store; `NotesListComponent` only receives inputs.
- **State: Signals + SignalStore, RxJS for HTTP/streams** – RxJS is not used as a store.
- **EF Core 9.x (not 10)** – EF Core 10 requires .NET 10. Versions are pinned exactly in the csproj; `Microsoft.EntityFrameworkCore.Relational` is referenced directly so the test project resolves the same EF version as the API.
- **Guid v7 ids generated by the application** – lets offline clients create notes without ID clashes (Phase 7) and keeps index inserts ordered.
- **One shared `AppDbContext`, module folders inside one project** – simplest while learning; split into projects/DbContexts later only if needed.
- **Optimistic concurrency with `Version`** – update requests carry the last seen version; mismatch returns 409. Reused by sync in Phase 7.
- **Soft delete through an EF query filter** – rows stay (needed for sync); queries hide them automatically.
- **Dev DB on host port 5433** – a local Windows PostgreSQL service already uses 5432. Connection string lives in user-secrets.
- **Swagger UI (not Scalar) for API docs** – more familiar to the user. OpenAPI JSON is generated by .NET 9's built-in `AddOpenApi`; only the UI package `Swashbuckle.AspNetCore.SwaggerUI` is added.
- **Tests use real PostgreSQL via Testcontainers** – no mocked DbContext; real migrations are applied.
