## Database

| Table | Owning module | Notes |
|---|---|---|
| `notes` (id uuid, title, content, created_at, updated_at, version, is_deleted, notebook_id, is_pinned, status text) | Notes | Soft delete via query filter; `version` is a concurrency token; `notebook_id` FK `ON DELETE SET NULL`; migrations `InitialCreate`, `AddNotebooksTagsAndPinning`, `AddNoteStatus` |
| `note_tags` (note_id, tag_id; composite PK) | Notes | Join table n-n; both FKs cascade |
| `notebooks` (id, name, parent_id, created_at, updated_at) | Notebooks | Self-FK `ParentId` (`RESTRICT`); hard delete |
| `tags` (id, name, normalized_name unique, created_at) | Tags | Unique index on `normalized_name`; hard delete |
| `users` (+ `user_claims`, `user_logins`, `user_tokens`: Identity) | Auth | Guid id, email, password HASH, lockout counters |
| `refresh_tokens` (id, user_id, family_id, token_hash unique, is_persistent, created_at, expires_at, revoked_at, revoked_by_rotation) | Auth | Only the SHA-256 hash of the token is stored; FK to users (cascade) |
| `notes`, `notebooks`, `tags` also have `user_id` (nullable only for pre-auth rows) | each module | FK to users (cascade); tag names unique per user; filtered by the current user in `AppDbContext` |
| `notes.search_vector` (generated tsvector, GIN `ix_notes_search_vector`) and trigram indexes `ix_notes_title_trgm`, `ix_notes_content_trgm` | Notes | Extensions `unaccent`, `pg_trgm`; function `f_unaccent(text)`; the indexes on expressions exist only in the migration |
| `note_revisions` (id, user_id, note_id, title, content, note_version, reason, created_at) | Notes | `reason` = `edit` (snapshot of the text BEFORE an edit, at most one per `Notes:Revisions:Interval`), `conflict` (text that lost a sync conflict) or `restore` (text replaced by a restore); capped at `Notes:Revisions:MaxPerNote`, oldest deleted; cascade FKs. No migration in Phase 11 (the table and column existed since Phase 7) |
| `sync_tombstones` (user_id, entity, entity_id, seq, at) | Sync | Written by AFTER DELETE triggers on notes/notebooks/tags so pull can report deletions (a purge from the trash writes none: the note was already reported deleted) |
| `sync_operations` (user_id, op_id; PK both, result) | Sync | Idempotency: a retried push returns the stored result instead of applying twice |
| `notes`, `notebooks`, `tags` also have `sync_seq` + `sync_at` (shadow properties, not in the entities) | each module | Stamped by BEFORE INSERT/UPDATE triggers from the global sequence `sync_seq` (covers FK `SET NULL` and bulk updates); index (user_id, sync_seq); migration `AddSync` is hand-edited SQL |
| `attachments` (id, user_id, note_id, file_name, content_type, size_bytes, storage_key, created_at) | Attachments | Id chosen by the client; `storage_key` = `<userId>/<attachmentId>` (no file name in it); both FKs cascade (note, user); filtered by the current user in `AppDbContext`; migration `AddAttachments`. The objects are in the storage, not here |

## Key entry points

- `global.json` – pins .NET SDK 9.0.x
- `.config/dotnet-tools.json` – local tool manifest (`dotnet-ef` 9.x); run EF commands as `dotnet dotnet-ef ...`
- `docker-compose.yml` – local PostgreSQL 17 (`db`, host port **5433** because a Windows PostgreSQL service owns 5432, volume `inknote-db-data`)
- **The whole system in Docker** (Phase 12a): `docker compose --profile app up -d --build` then http://localhost:8080. Needs `JWT_KEY` in a local `.env` (copy `.env.example`; other values have dev defaults). Services: `api` (image from `src/backend/Dockerfile`: multi-stage, .NET 9 SDK → aspnet runtime, non-root, port 8080, NOT published to the host, healthcheck by `/dev/tcp`), `web` (`src/frontend/Dockerfile` + `nginx.conf`: Angular `container` build served by nginx-unprivileged on 8080 → host `${WEB_PORT:-8080}`; `/api/` and `/hubs/` (WebSocket) are proxied to `api`; `index.html`, `ngsw*.js`, manifest are `no-cache`, hashed files cached 1 year), plus `db` and `storage`. A plain `docker compose up -d` still starts only `db` + `storage` (profile `app` is opt-in). `.dockerignore` in both folders
- Container settings (environment variables in `docker-compose.yml`): `Database__MigrateOnStartup=true` (the API applies the migrations itself; default OFF, tested in `MigrateOnStartupTests.cs`), `Storage__ServiceUrl=http://storage:9000` (server) vs `Storage__PublicUrl=${STORAGE_PUBLIC_URL}` (browser), `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` (trust nginx's X-Forwarded-*; safe only because the API is not published)
- **Logging** (Serilog, Phase 12d): configured in `Program.cs` (`UseSerilog`, `UseSerilogRequestLogging`) and the `Serilog` section of `appsettings.json` (levels, Console sink; `Microsoft.AspNetCore` stays at Warning so the URLs with `?access_token=` of the SignalR connection are never logged). One line per request with method, PATH (never the query), status and time; `/api/health` is not logged; 4xx = warning, 5xx = error. RULE: never log note text, tokens or passwords. Tests: `LoggingTests.cs` (a `CapturingSink` reads everything logged after secrets were sent through the API)
- **Colors**: `--ink-title` (the app name and the title of the open note) and `--ink-editor-text` (plain paragraphs in the editor) are black in the Light theme and equal to `--ink-text` in Dark and Warm; the editor puts `--ink-text` back on list items, tables and code through the line classes `cm-md-list` / `cm-md-table` / `cm-md-code` (`markdown-live-style.ts`), headings and quotes have their own colors
- **End-to-end tests** (Phase 12b): `src/frontend/e2e/*.e2e.ts` + `playwright.config.ts` (`@playwright/test`, the Chrome installed on the machine). They run against the WHOLE system in Docker: start it with `docker compose --profile app up -d --build` (JWT_KEY in .env; `POSTGRES_DB=inknote_e2e` keeps your notes apart), then `npm run e2e` in `src/frontend`. Tests: `sync.e2e.ts` (second device, real time, deep link + refresh cookie, login redirect, offline with the service worker), `attachments.e2e.ts`, `transfer.e2e.ts` (export, import into another account, left-out report; use `app-transfer-page input[type=file]`, the sidebar has a hidden file input too), `organize.e2e.ts` (drag a note into a folder and out again, folder menu export/import, new items at the top level after a click on the empty space), `editor.e2e.ts` (the selection toolbar with the keyboard and with a real mouse drag, focus loss, undo); `support.ts` = helpers (`register`, `newNote`, `settled`, `titleInput` ...).
